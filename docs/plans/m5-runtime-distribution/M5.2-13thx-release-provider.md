# M5.2 — 13thx GitHub Release Provider

## Goal

Implement read-only release discovery for project-owned components published under `13thx-mcp`.

## Prerequisites

- M5.1 merged and green.
- Read `COMMON.md` and M5.1 handoff.
- Inspect actual current GitHub Release asset contracts before coding if they changed.

## Current release contract

Repositories:

```text
13thx-mcp/filesystem
13thx-mcp/git
13thx-mcp/exec
13thx-mcp/gateway
13thx-mcp/studio
13thx-mcp/fleet
```

Rust/service assets currently follow:

```text
<binary>-vX.Y.Z-darwin-amd64.tar.gz
<binary>-vX.Y.Z-darwin-arm64.tar.gz
SHA256SUMS.txt
```

Fleet:

```text
mcp-fleet-vX.Y.Z.tar.gz
SHA256SUMS.txt
```

## Scope

Implement the `13thx-mcp` provider behind the M5.1 release-provider abstraction.

Required capabilities:

- query latest normal release;
- optionally query an explicit semantic version/tag;
- reject draft releases for normal update use;
- define prerelease behavior explicitly (default should not silently promote prereleases into stable channel);
- parse release tag/version;
- enumerate assets;
- identify checksum manifest asset;
- return typed asset metadata for later platform resolution/staging;
- capture immutable release identifiers where useful.

## Network behavior

Use an explicit HTTP client with:

- HTTPS-only trusted API endpoints;
- bounded connect/request timeout;
- bounded response size where practical;
- clear User-Agent;
- structured error mapping;
- no logging of authorization headers/tokens.

Public releases should not require user credentials. If authenticated GitHub requests are supported later for rate limits/private assets, design secret handling separately and do not expose tokens to the browser.

## Asset selection boundary

Do not fully implement OS/arch selection here. M5.4 owns platform resolution. This provider should return enough structured asset metadata for M5.4 to choose deterministically.

Do not download release archives here. M5.5 owns artifact retrieval/staging.

## Failure semantics

Distinguish at least:

- repository/provider unreachable;
- HTTP error;
- malformed release metadata;
- invalid tag/version;
- no stable release;
- missing checksum manifest;
- duplicate/ambiguous checksum manifest;
- explicit requested version not found.

## Implementation evidence — 2026-09-17

Canonical M5 integration history records this submission on `feat/m5-runtime-distribution` as `ec75372` (`feat(update): implement M5.2 GitHub release provider`), directly after M5.1, without starting M5.3 or adding archive download/activation behavior.

### Provider implementation

- Concrete provider: `src/update/thirteenthx.rs` exporting `ThirteenthXReleaseProvider` behind the unchanged M5.1 `ReleaseProvider` trait.
- Trusted authority remains `ComponentCatalog`: every lookup re-resolves the supplied `ComponentId` and uses the catalog-owned provider/owner/repository mapping. Mutating the `source` fields on a supplied `ComponentPolicy` cannot redirect a request.
- Production metadata origin is fixed to `https://api.github.com`; callers cannot provide a base URL, repository URL, release URL, checksum URL, executable path, or install path.
- HTTP client uses HTTPS-only requests, a 3-second connect timeout, 10-second request timeout, Studio-specific User-Agent, bounded response streaming (1 MiB release metadata / 256 KiB checksum manifest), and a redirect policy limited to HTTPS GitHub/GitHubusercontent hosts.
- No authorization header/token path was added; public release discovery remains credential-free and provider errors do not log headers or response bodies.
- Structured provider failures distinguish unreachable transport, HTTP status, oversized response, malformed metadata, invalid tag, no stable release, explicit-version absence, ineligible draft/prerelease, missing/duplicate checksum manifest, and untrusted asset URL.

### Release/channel semantics

- Latest lookup uses GitHub's normal `releases/latest` endpoint and still verifies that returned metadata is neither draft nor prerelease.
- Explicit lookup accepts validated stable semantic versions and requests `releases/tags/v<version>`. Semantic prerelease versions are rejected before network access; draft/prerelease responses are rejected from the stable channel.
- Release tags must start with `v` and parse through the M5.1 `Version` semantic-version wrapper.
- Non-zero immutable GitHub release/asset IDs are required at metadata parse time.
- All uploaded assets are preserved as typed `ReleaseAsset { name, download_url }` metadata after validating HTTPS `github.com/<trusted-owner>/<trusted-repo>/releases/download/...` origin/path.
- Exactly one uploaded `SHA256SUMS.txt` is required and its trusted URL is returned as `AvailableRelease::checksum_manifest_url`.
- `checksum_manifest()` performs bounded retrieval of that small manifest only. It does not parse/verify archive checksums; M5.5 owns that step.
- `select_asset()` remains fail-closed with an M5.4 ownership error; no OS/architecture matching was implemented early.

### Current release-contract verification

The checked-in release workflows were treated as the current repository source of truth because an unauthenticated live GitHub API probe to `13thx-mcp/filesystem/releases/latest` returned HTTP 404 in this environment. Automated tests therefore remain hermetic as required.

Verified checked-in workflows:

- `filesystem`, `git`, `exec`, and `gateway`: `rust-mcp-<component>-vX.Y.Z-darwin-amd64.tar.gz`, `rust-mcp-<component>-vX.Y.Z-darwin-arm64.tar.gz`, plus `SHA256SUMS.txt`.
- `studio`: `mcp-studio-vX.Y.Z-darwin-amd64.tar.gz`, `mcp-studio-vX.Y.Z-darwin-arm64.tar.gz`, including `web/dist`, plus `SHA256SUMS.txt`.

- M5.1 also maps `blender` to `13thx-mcp/blender`, but no checked-in Blender release workflow exists in the current workspace. The provider preserves the M5.1 catalog contract and will return typed `NoStableRelease`/provider metadata errors when no publishable release exists rather than inventing an alternate source.

M5.3 can reuse the M5.1 `ReleaseProvider` trait and the provider-error taxonomy but must keep OpenAI tunnel repository authority separate from `github_13thx`. M5.5 must still verify checksum contents and archive structure before any staging/activation.
