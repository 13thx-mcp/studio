## Scope

M8.1 establishes the automation foundation only. It does **not** enable:

- periodic release-provider checks;
- automatic staging;
- automatic update activation;
- automatic process restart;
- automatic reconciliation mutation.

Missing `[automation]` remains manual/disabled.

## Implemented foundation

### Configuration

Studio now accepts validated additive `[automation]` configuration with:

- startup grace;
- health/cleanup cadence;
- update policy/cadence/failure/circuit/staging bounds;
- reconciliation policy/cadence/failure/circuit bounds;
- restart policy/backoff bounds;
- explicit UTC maintenance window.

All policy enums default to manual/disabled.

The loaded configuration identity is bound into automation state as the policy/config fingerprint.

### Automation state

`runtime/studio/data/automation/state.json` schema v1 stores bounded non-secret policy state:

- due schedules;
- failure circuits;
- deferral/backoff state;
- current-process prepared references;
- last outcome code;
- policy/config fingerprint;
- last persisted wall time.

The store:

- is capped at 256 KiB;
- rejects future/corrupt schema;
- rejects state-file and ancestor symlinks;
- remains confined below the trusted runtime root;
- uses create-new sibling temporary file, file fsync, atomic rename and parent-directory fsync;
- does not overwrite corrupt/future state with defaults.

### Scheduler and circuit foundation

The ScheduleEngine:

- uses startup grace;
- enables update/reconciliation schedules only when their policy is non-manual;
- collapses missed intervals to one due evaluation;
- has one serialized controller evaluation at a time;
- rejects duplicate controller run loops;
- separates deferrals from failures;
- applies persisted bounded exponential coordinator deferral from 30 seconds to 30 minutes;
- supports closed/open/half-open failure circuits;
- detects backward wall-clock movement beyond the frozen tolerance.

M8.1 scheduled evaluations deliberately perform no release/network/runtime action.

### Shared audit admission

`OperationService` now owns asynchronous access to the existing M6:

- `HistoryHandle::admit_operation`;
- `HistoryHandle::finish_operation`.

Existing HTTP/manual mutations route through the shared service without changing response/effect/audit semantics.

The production AutomationController receives the same `OperationService` instance that is installed in `AppState`. The service fails admission closed when history is unavailable.

M8.1 intentionally does not add a new `system_automation` M6 actor because there is no background mutation producer yet. The first M8.3 background check/prepare producer must introduce the explicit actor/action migration before it can emit automatic operation evidence. This does not weaken M8.1: there is no automation mutation path to bypass admission.

### Startup and shutdown

The controller is constructed only after:

- component update/recovery owners are constructed;
- Tunnel recovery runs;
- Studio self-update finalization runs;
- startup runtime reconciliation check completes.

It starts only after Studio binds and marks the run ready.

Graceful shutdown cancels and bounds controller termination before Tunnel/MCP supervisor shutdown.
