# M8.6 — Durable Hazard Holds and Recovery Hardening

**Status:** BLOCKED BY M8.0

## Objective

Make unknown side-effect risk and automation recovery survive process restarts as bounded safety state without creating a replay queue.

## Primary repositories/source areas

### Gateway

- policy ToolClass → telemetry
- telemetry DTO
- durable safety-hold store
- control response capabilities/status
- hold resolution
- targeted child control prerequisite for M8.4

### Studio

- GatewayControlClient
- automation safety adapter
- startup recovery
- staging cleanup
- diagnostics/history projections

### Fleet

- self-update lock/recovery compatibility
- runtime-only recovery validation

## Safety-hold ordering

For terminal Unknown unsafe request:

```text
classify from admitted server policy
→ build sanitized hold
→ atomically persist hold
→ expose hold in safety status
→ record telemetry projection
→ return unknown/non-retryable result
```

If persistence cannot be proven, automation safety capability becomes unavailable.

## Targeted child control

This package freezes/implements the Gateway-side primitive consumed by M8.4:

- capability advertised;
- child identity validated;
- unsafe active work blocks;
- child generation replacement is bounded;
- candidate initialization/catalog verification;
- sibling isolation;
- result reports generation/health/identity evidence.

It does not update binary bytes itself.

## Recovery cleanup

- inspect ready staging at startup;
- identify current-process references;
- enforce TTL/budget only on cleanup-eligible staging;
- fail closed on unsafe path/symlink/tamper;
- never delete component journals/rollback authority;
- stale cross-process lock requires owner-specific proof.

## Exit criteria

R10–R19 and R48–R50 PASS. M8.4 may enable automatic mutation only after these capabilities are qualified.
