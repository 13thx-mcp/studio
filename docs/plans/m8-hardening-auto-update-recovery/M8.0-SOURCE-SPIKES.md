# M8.0 Source Feasibility Spikes

**Date:** 2026-09-22
**Status:** PASS — accepted contracts have concrete implementation anchors; no production M8 behavior was added.

This document records source-level feasibility checks used to close M8.0. It is not runtime qualification.

Exact audited source heads: Gateway `469ec9258855d39d9a3f57bae60ff4810ffeafb1`, Fleet `2ccdf54495e23c86da5bc8f6799b44d225c2e136`, Git MCP `31ceadd79751c3be7aed197697c88d74c594b812`, against the Studio M7 runtime baseline `ab9aca19c3fc6091ca3d9d169f5fc2a314b8d476` and M8 planning baseline `cab90a8aa2915bebfe16dd5c43e99b9a9049afb4`.

## S-01 — Automation state / audit extraction

Current source already provides durable atomic-write patterns in registry, reconciliation and self-update domains.

The existing API helper `admit_local_operation` delegates authority to:

```text
HistoryHandle::admit_operation(subject_kind, action, ActorKind::LocalOperator)
```

and terminal evidence delegates to `HistoryHandle::finish_operation`.

**Conclusion:** ADR 0037 can extract an internal admission/terminal service without changing M6 authority. HTTP response headers remain API presentation only.

## S-02 — Gateway classed unknown hold ordering

Current Gateway call path resolves a trusted route and active strict policy before dispatch. `ToolClass` already exists as a server-owned serializable enum:

```text
read
mutation
long-running
control
```

The current `route_limits()` projection drops class and returns only child/tool concurrency.

After dispatch, all timeout/cancel/transport-close unknown paths pass through a common area where Gateway still has:

- request ticket/request ID;
- child;
- original tool name;
- catalog/profile generation;
- request timing.

**Implementation anchor:** extend route admission metadata to carry ToolClass, then pass it into request observation and the ADR 0040 hold-persist path before returning terminal Unknown.

**Conclusion:** durable classed hold ordering is feasible without caller-supplied classification or request replay.

## S-03 — Global drain + targeted child restart

Gateway `begin_drain()` already:

1. increments/returns a drain generation;
2. changes phase to Draining;
3. closes scheduler admission;
4. waits for coordinator idle;
5. moves to Drained on success.

`resume(generation)` already rejects stale generations and re-opens admission.

Gateway state already holds per-child runtime, status and recovery generation. Existing reload/recovery code already creates candidate child runtimes and preserves generation/recovery metadata.

**Conclusion:** ADR 0041 can add `restart_child` only while the matching global drain generation is Drained. No per-child drain scheduler is required in M8.

The implementation must factor/reuse child candidate initialization rather than use full `reload()`, because full reload may churn healthy sibling processes.

## S-04 — Studio control client compatibility

Gateway control responses already contain:

- active request count;
- queued request count;
- drain generation;
- catalog generation;
- profile generation.

Studio currently deserializes only a subset.

Serde response extension is additive. New Studio can read optional/default M8 fields and capability-gate new actions. Older Gateway rejects new actions, but Studio does not send them without advertised capability.

**Conclusion:** P-03/ADR 0041 are additive and backward-compatible for manual M7 operation.

## S-05 — Fleet host schema v3

Fleet host profiles are TOML-loaded and rendering already branches on `schema_version` for Gateway policy behavior. `studio_config_text(host)` is already the deterministic owner of the Fleet-managed Studio config surface.

**Conclusion:** Fleet 0.5 can add explicit schema-v3 validation and render `[automation]` into the existing `studio.config` surface. Schemas 1/2 can continue to omit M8 automation and therefore inherit manual Studio defaults.

No second Fleet-managed automation file is required.

## S-06 — Loaded-policy freshness

RuntimeReconciler already records canonical loaded Studio config digest/process instance and persists `studio_restart_pending`. It distinguishes file convergence from runtime activation.

**Conclusion:** ADR 0043 can block destructive automation whenever the Fleet-managed Studio config changed but the current process has not proved the new digest.

Prepared automation references can bind the same loaded config SHA-256.

## S-07 — Prepared staging versus recovery authority

Current generic/Gateway/Fleet transaction records are process-local while ready staging persists.

Current owners already expose separate recovery material:

- generic MCP finalized sibling rollback + checksum;
- Fleet candidate/rollback/failed sibling directories and interrupted-swap recovery;
- Tunnel schema-versioned recovery journals plus candidate/rollback/failed release dirs;
- Studio self-update durable metadata/candidate/releases and external Fleet activation lock;
- reconciliation backup + managed-state manifest.

**Conclusion:** ADR 0039/0044 can classify previous-process ready staging as non-authoritative while preserving all owner-specific recovery material.

Generic cleanup must never decide recovery authority from filename age alone.

## S-08 — Self-update controller handoff

`SelfUpdateManager::finalize_startup()` already treats Fleet as terminal activation/rollback authority and leaves Staged state non-terminal without inferring success.

**Conclusion:** new AutomationController can start only after self-update finalization/recovery and Studio readiness. The old controller cannot assume the update succeeded before shutdown.

## S-09 — Guarded prerelease release tagging

Git MCP guarded release tag flow already enforces:

- clean protected main;
- two-parent no-ff merge HEAD;
- exact current-HEAD release evidence for enrolled repos;
- immutable existing tag behavior;
- exact release-prep subject checks via the same version validator.

The only blocking constraint is `validate_semver_core()`, which rejects prerelease suffixes.

**Conclusion:** ADR 0045 requires a narrow parser/subject-description change plus permanent tests; it does not require weakening release evidence or using generic `git_tag`.

## S-10 — Recovery/diagnostics ownership

Source constants and recovery functions identify separate owner domains for generic MCP, Fleet, Tunnel, Studio self-update and reconciliation material.

**Conclusion:** ADR 0044 can implement an allowlist cleanup classifier. There is no justification for a broad recursive "old file" garbage collector.

## Freeze result

Every P-01..P-19 prerequisite now has:

- an accepted ADR owner;
- a concrete source integration point;
- a verification requirement in R01..R65;
- no need to enable production auto mutation in M8.0.

M8.1 may begin from this contract baseline. M8.4 remains blocked until the implemented M8.2/M8.6 safety capabilities pass their permanent verification.
