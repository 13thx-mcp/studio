## Scope

M8.2 adds typed health evidence, bounded Studio-owned restart policy, and additive Gateway safety/status capability needed by later automatic activation.

M8.2 does **not** enable automatic activation. Gateway durable unknown-outcome holds and targeted child restart are M8.6/M8.4 work.

## Studio implementation

### Typed health

New `HealthSnapshot` evidence preserves:

- component identity;
- observed/freshness time;
- healthy/degraded/unhealthy/unknown state;
- liveness/readiness distinctions;
- ownership and identity evidence;
- required/failed checks.

Missing/stale/unknown evidence never authorizes automatic mutation.

Gateway health consumes control-socket status and child summaries. Generic MCP health combines installed identity with known running-owner evidence. Tunnel keeps liveness/readiness/MCP/control-plane probes separate.

### Restart reliability

Studio-owned MCP and Tunnel supervisors now support the M8 restart policy primitives:

- disabled/on-failure;
- explicit `desired_running`;
- explicit Stop clears restart intent before signaling;
- bounded exponential backoff;
- stability window;
- circuit-open state;
- runtime-operation conflict deferral without counting a crash failure;
- restart suppression while conflicting update/reconciliation/control ownership exists.

Gateway child restart remains Gateway-owned; Studio does not add a competing child restart loop.

## Gateway implementation

Gateway control status is extended additively with:

- existing `active_requests`;
- existing `queued_requests`;
- catalog/profile/drain generations;
- `capabilities`;
- `automation_safety_available`;
- `safety_hold_count`;
- bounded child summaries.

M8.2 advertises:

`m8_child_status`

The child summary contains:

- name;
- enabled/running;
- generation;
- recovery state;
- consecutive failures;
- retry time;
- tool count.

No argv, environment, executable path or payload is added to the control response.

`automation_safety_available` remains **false** in M8.2 because durable M8 safety holds are not implemented until M8.6. New Studio therefore cannot mistake child-status capability for mutation-safety capability.

Older Gateway responses remain parseable through optional/default fields, but cannot authorize automatic mutation.
