# M8.4 — Safe Automatic Activation and Runtime Ownership Coordination

**Status:** BLOCKED BY M8.2 + M8.3 + M8.6 HAZARD/CHILD-CONTROL PREREQUISITES

## Objective

Implement `auto-update-safe` with a final activation-time SafetyGate and explicit component/runtime ownership coordination.

## Primary source areas

- AutomationController/SafetyGate
- generic McpUpdateManager
- GatewayUpdateManager / GatewayControlClient
- Gateway targeted child control
- Fleet/Tunnel/Self update adapters
- RuntimeOperationCoordinator
- source hygiene adapter

## Activation-time global gate

- mode is auto-update-safe;
- maintenance window open;
- clock state sane;
- current-process prepared authorization valid;
- audit admission available;
- runtime coordinator can be acquired;
- no unsafe Gateway hold;
- required Gateway capabilities/fresh status available;
- source hygiene safe when source exists;
- installed source version unchanged;
- staged fingerprint unchanged;
- rollback material available;
- component owner stable/healthy enough for transition.

## Generic MCP activation

A flat MCP binary may be owned simultaneously by:

- Studio direct Supervisor registration;
- Gateway child runtime.

Automatic activation must:

1. identify all active owners;
2. prevent unsafe Gateway work from being interrupted;
3. stop/quiesce the Studio-owned process if running;
4. replace bytes transactionally;
5. start/verify the Studio-owned process if previously running;
6. targeted-restart/reinitialize the Gateway child if it owns the component;
7. verify target child generation/identity/catalog;
8. rollback both runtime ownership surfaces if activation verification fails;
9. never restart healthy unrelated Gateway children unnecessarily.

Exact ordering is frozen in ADR 0041 and component update ADR amendments before code.

## Other components

Gateway, Fleet, Tunnel and Studio retain their existing specialized update transaction/recovery owners. Automation supplies policy/admission only.

## Failure semantics

Once physical mutation begins, maintenance-window closure/policy disable does not interrupt required completion/rollback.

Unknown physical outcome opens operator/recovery state; scheduler does not launch a second activation.

## Exit criteria

R34–R41 PASS, including full generic MCP Gateway-child coordinated activation.
