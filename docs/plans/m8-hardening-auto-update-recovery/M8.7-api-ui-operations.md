# M8.7 — Operator API, UI, Audit and Diagnostics

**Status:** BLOCKED BY M8.3–M8.6 DOMAIN CONTRACTS

## Objective

Expose M8 state and intervention safely without introducing raw command authority.

## API surface direction

Read:

- automation status/policy effective state;
- next due times;
- update/reconciliation circuits;
- deferral blockers;
- prepared transaction summary;
- Gateway safety holds;
- health summaries;
- diagnostics generation status.

Mutations:

- check now;
- reset circuit;
- resolve safety hold;
- activate prepared now through the same SafetyGate;
- trigger safe reconciliation through the same gate;
- generate diagnostics.

Every browser mutation requires same-origin enforcement and shared audit admission.

## UI requirements

Clearly distinguish:

- available update;
- prepared;
- deferred;
- activation blocked;
- activating;
- recovery required;
- safety hold open;
- circuit open.

Do not present "prepared" as "updated".

Hold resolution UI must explicitly say it does not retry or determine the historical tool result.

## Diagnostics

Bounded archive using the allowlist in RECOVERY-AND-SAFETY. Add secret canary tests and archive size cap.

## Exit criteria

R51 and R53–R57 PASS plus frontend reconnect/state tests.
