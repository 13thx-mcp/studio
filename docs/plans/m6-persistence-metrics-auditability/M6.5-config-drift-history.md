## Implementation sequence
1. Record exact already-loaded Studio config identity privately with loaded_by run link; do not reread and call the result the loaded configuration.
2. From the M6.2 serialized registry mutation receipt create safe revision/change-category events. Discovery approval is only completed after the registry commit succeeds; candidate scan is not approval.
3. Hook managed manifest file commit receipts in check/adopt/apply/rollback. Existing check can adopt a legacy baseline or change restart-pending metadata and must record the actual effect.
4. Keep written/desired/loaded/restart-required identities distinct. Record a new process’s exact loaded proof clearing a pending restart, not a periodic status snapshot falsely clearing it.
5. Record normalized drift check/adopt/apply/rollback observations with affected surface codes and private digest links. Config revision returning to earlier content is a new observation revision, not a duplicate event.
6. Bootstrap only validated safe projections; absent fleet/state is absence, not a reason to create an authoritative manifest from SQLite. External changes outside observation coverage produce an unknown actor/time interval.
7. Join config and artifact lineage by recorded operation/run evidence only. Verify retention boundaries do not leave a misleading complete chain.

## Failure semantics
File commit remains authoritative even if historical receipt fails afterward; return actual effect plus audit warning. Source manifest failure preserves existing rollback/backup behavior. Repeated GET/status does not create false revisions or mandatory mutation audit.
