## Implementation sequence
1. Implement exact endpoint/filter/DTO contracts in API-AND-UI.md using prepared finite query templates and two read workers. Health uses an in-memory sanitized snapshot when store unavailable.
2. Implement versioned cursors with db/retention epoch, immutable ordering, high-water sequence and filter binding. List projections are as of the cursor snapshot, not later mutable outcomes.
3. Add origin/Host/no-store/CORP boundary to new endpoints and forbid history action authority. Existing live transaction APIs retain owner semantics.
4. Publish coalesced post-COMMIT history watermarks. Subscribe before history handshake snapshot; reconnect/lag causes bounded REST refresh, not speculative state replay into owners.
5. Build accessible timeline/session/update/drift/lineage views and SVG charts with tabular alternative. Distinguish exact/lower-bound/unknown, live/history, written/loaded and domain/audit outcomes.
6. Bound client retained rows, cancel stale filter requests, handle decimal sequences and epoch resets. LocalStorage is hints/preferences only.
7. Exercise empty/loading/error/partial/pruned/offline and post-effect audit warning states with component tests and a temporary real backend browser flow.

## Failure semantics
503 store/read-pressure state leaves live status and safe controls independently available. Cursor expiration restarts pages explicitly. Unknown/partial metric data never renders as zero or an exact uninterrupted trend. Missing historical transaction cannot imply resume/apply availability.
