# M6.1 — SQLite foundation, migration engine and safe operations

**Status:** NOT STARTED. This is an implementation plan, not execution evidence.

## Objective
Provide a bounded, private history service that opens/migrates safely, reports failures honestly and cannot interfere with existing runtime recovery.

## Implementation sequence
1. Add exact rusqlite candidate with selected features and a minimal UUID-v4 dependency; resolve Cargo.lock once and audit the graph. Capture linked sqlite_version/source_id/compile options; reject an unpatched engine.
2. Implement HistoryConfig finite local limits without a DB pathname option. Introduce injectable Clock, StoreFault and filesystem seams for tests, not production fault knobs exposed over HTTP.
3. Implement fixed path validation, private creation, retained advisory ownership, sidecar checks and no-follow behavior. Contending writer never marks another run interrupted.
4. Implement dedicated writer plus two bounded read workers, enum commands, queued oneshot receipts, deadlines, health snapshots and explicit shutdown. No detached per-event threads or SQL on Tokio.
5. Apply pragmas/readback, application identity, embedded migration ledger/checksum, transactional migration, quick/full checks and future-version rejection. The worker must never call a runtime owner.
6. Expose a real degraded service on open/migration/timeout failure; wire composition before existing owner startup without changing M5 recovery order or listener/activation-ready proof. Start no lifecycle producer yet.
7. Implement fixed-destination backup/verify CLI paths under the existing --config convention. Test consistent WAL backup and offline schema-upgrade prerequisite; migration over budget disables history rather than holding startup hostage.
8. Add store inspection test helpers and metrics placeholders only as types; later packages own event semantics and counters.

## Failure semantics
Fail the history store closed for corrupt/unsafe/future schema. Bound admission/open/query waits, account for uncancellable blocking I/O and late receipts, preserve bytes. Never silently create a fresh DB or fall back to an in-memory production database. Existing physical owner behavior remains unchanged by this foundation.
