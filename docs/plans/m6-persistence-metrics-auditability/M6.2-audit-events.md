## Implementation sequence
1. Reproduce P-01 with a held control lease and a generic MCP apply, then fix apply to acquire the existing component coordinator lease before its manager-local lease. Test a conflicting reconciliation/control operation and distinct safe component concurrency.
2. Reproduce P-02 with barrier-controlled mutations to two registry entries, then serialize complete snapshot/validate/file-commit/replace and capture an immutable receipt. No SQL await in that mutation section; direct calls receive the same protection.
3. Implement closed event payloads, source-stream ordinals, idempotency digest checks, schema-version validation and atomic event/projection receipts. Do not route recording through EventHub.
4. Implement OperationContext for local operator, startup, shutdown, compensation and external observation. Root owner admits once; nested stop/start/rollback inherits context and never recursively acquires a conflicting lease or blocks compensation on fresh audit admission.
5. Add bounded durable admission and reserved terminal capacity. Expired/late admissions must never dispatch. Ensure an HTTP cancellation cannot leave a newly introduced half-executed physical phase: operation ownership stays with a bounded tracked owner task until its original compensation/terminal path is done.
6. Add response correlation/effect/audit headers and health snapshots. Post-effect audit failure leaves the actual domain result intact and warns; pre-effect rejection says no effect began.
7. Add exhaustive required-action-family coverage tests with fake owners, while concrete transition producers are delivered in M6.3–M6.5. Keep status honest about those remaining gaps.

## Failure semantics
Pre-effect mandatory commit failure blocks dispatch. Post-effect failures cannot trigger rollback/retry or hide a required source-journal failure. Safety exceptions enqueue without blocking before their physical action. No infinite retry queue and no claim of exactly-once physical effects across filesystem/SQLite.
