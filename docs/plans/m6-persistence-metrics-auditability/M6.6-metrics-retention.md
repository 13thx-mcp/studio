## Implementation sequence
1. Implement definition version 1 exactly as METRICS-AND-RETENTION.md: launches, restart attempts, crashes by owner semantics, closed exact-session average, check outcomes, apply attempts/outcomes/rollback and scoped verified LKG.
2. Consume only canonical qualifying facts, excluding imported bootstrap terminal evidence from new-operation counts. Persist source batch contributions and watermark atomically so retry/late journal scans cannot double-count.
3. Produce hourly/daily/totals with separate watermarks and quality, using observation time for buckets and monotonic durations only where exact. Unknown is not zero.
4. Install finite housekeeping from startup plus max once per 60 s. It may compact/checkpoint/expire history only; no release provider, reconcile or lifecycle calls.
5. Enforce finite event/DB/WAL pressure limits, terminal reservation and bounded batches. Aggregate through a safe deletion boundary, expire only eligible classes, and retain bounded lineage summaries with explicit ancestry boundaries.
6. Advance global retention epoch with membership-changing deletion; expire incompatible browser cursors. Protect active records without unlimited pinned ancestry; hard pressure rejects new discretionary admission.
7. Test restart during aggregate/delete/checkpoint and verify replay plus remaining audit consistency. Report operator policy, not compliance guarantees.

## Failure semantics
Aggregation failure never changes runtime result. Lag/partial coverage is visible. Hard pressure stops new mandatory-audit admissions; safe actions remain possible, with explicit incomplete evidence. Checkpoint/retention failure never triggers full DB deletion or source journal cleanup.
