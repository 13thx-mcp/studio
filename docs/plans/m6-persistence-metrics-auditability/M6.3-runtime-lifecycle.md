## Implementation sequence
1. Capture a Studio run identity before owner startup; after successful history open identify previous nonterminal observation runs under store ownership and mark observer interruption, not child death.
2. Hook start request/admission, generation/state capture, actual successful spawn/PID assignment and failed-spawn outcome at the audited source points. Failed spawn is not a session/launch.
3. Preserve the child wait-monitor setup and stop responsiveness: do not await SQLite before the monitor is installed or while a state mutex is held. Capture original start identity/duration in immutable terminal facts before clearing started_at/PID.
4. Hook requested stop, terminal exit classification, restart-attempt ordinal and parent operation; preserve MCP clean-zero versus Tunnel unexpected-zero behavior and existing counters.
5. Coalesce a 15 s observation heartbeat per active session into last-seen lower-bound data. This is history sampling only, not a health/restart policy; gaps stay unknown.
6. On graceful shutdown stop owners in the existing order, then bounded history drain and clean run closure only if owner shutdown and required capture succeeded. DB stall must not delay the physical signals.
7. Bootstrap safe current observations; never spawn/reconnect/signal from a historical PID. Keep existing live ProcessStatus counters per-run and add historical totals only through distinct history APIs.

## Failure semantics
Spontaneous exit and safe shutdown complete during DB failure. Unknown terminal events yield interrupted/partial history, null exact duration/exit code and no inferred crash. Old source ordinals cannot regress a closed session even when messages arrive out of order.
